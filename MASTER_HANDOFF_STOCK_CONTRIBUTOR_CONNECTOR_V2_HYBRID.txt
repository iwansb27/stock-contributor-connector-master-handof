BLOCK 02 — GENERATE METADATA

BLOCK 04 — DESKRIPSI

- No automatic submission to Shutterstock.

BLOCK 05 — KATEGORI
- Display/select the Shutterstock category options required by the current Shutterstock contributor UI.
- User chooses the category manually.
- Button/interaction should make clear that category is selected on the platform, not copied from AI.
- Persist the user's selected category locally if useful for the Job.
- Do not pretend that category has been submitted to Shutterstock.

BLOCK 06 — KEYWORD
- Display generated keywords.
- Button: COPY.
- Prefer a single COPY ALL for the keyword list.
- No CSV requirement for the user.

BLOCK 07 — KIRIM GAMBAR
- Reuse the existing successful Shutterstock image-transfer engine.
- This action transfers the image only.
- Do not attach a false metadata-success state to this action.
- On confirmed transfer:
  FILE_TRANSFERRED / IMAGE_TRANSFERRED.
- On failure:
  TRANSFER_FAILED.
- Audit the transfer event.

BLOCK 08 — BUKA SHUTTERSTOCK CONTRIBUTOR
- Add a direct button/shortcut to open the Shutterstock Contributor submission page.
- The user should not need to search/type the site manually.
- This button only opens the platform.

BLOCK 09 — MANUAL PLATFORM METADATA
User completes on Shutterstock:
- Paste Title.
- Paste Description.
- Select Category from Shutterstock's own UI.
- Paste Keywords.
- Complete any other platform-required fields visible at that time.

The connector must not claim platform metadata success merely because the user clicked the open button.

BLOCK 10 — FINAL SUBMIT
- User presses Shutterstock's own final Submit button manually.
- Connector must not fake or infer final submission.
- V2 status should distinguish:
  READY_FOR_MANUAL_SUBMIT
  from
  SUBMITTED
  from
  PENDING_REVIEW
  from
  ACCEPTED/REJECTED where evidence is actually available.

============================================================
15. GITHUB ACTIONS WORKFLOW — REFERENCE
============================================================

For a STATIC site, the workflow pattern is:

name: Deploy to GitHub Pages

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - name: Checkout
        uses: actions/checkout@v6

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v4
        with:
          path: '.'

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

Do not install this blindly into the handoff-only repository unless it contains an actual website entry file.
